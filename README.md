# Letterpress test10 — no-Canvas wake diagnostic control

Version `0.1.0~test10`. This RootHide SpringBoard injection tweak and Preferences bundle derive from the frozen, fully validated test9 source tree. The existing CADisplayLink wrapper and clock helpers are preserved byte-for-byte. The Vortex particle Canvas branch is replaced by a tiny, time-varying 4×4 white SwiftUI marker. The marker consumes the published clock date, so it exercises a changing SwiftUI value while the wrapper is mounted. No particles are rendered in this temporary diagnostic control build.

This removes the Vortex Canvas, particle-system update, draw calls, and symbol rendering from the `VortexView` body. The original simulation model, symbols storage/initialization, and draw implementation remain in source but are not invoked by that body. The marker is not an equivalent rendering workload; it does not prove a frame was submitted for every CADisplayLink callback. If the HUD is unmounted, the existing wrapper lifecycle stops the clock. Therefore a changed wake result can help separate the no-Canvas condition from the test9 configuration, but cannot by itself prove Canvas or a specific GPU/driver function is the unique cause.

Lyrics, SpringBoard host/window/scene registration, secure-window/SBS policy, media handling, settings, user defaults, identity, and preference configuration remain unchanged. No diagnostic sampler or export UI is included; this test build does not create or upload diagnostic reports. It is not a confirmed fix or a production visual build.

Install manually over the same package and respring. Keep the same track and settings. Confirm real lyrics are visible and the tiny marker appears/changes, then lock for 5–10 seconds and wake twice. Report whether wake delay remains. The absence of particles is intentional. Keep test9 and isolate6 available as comparisons; no repeated JSON is needed.
